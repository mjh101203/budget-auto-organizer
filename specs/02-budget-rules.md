# 02 · 예산 항목 · 자동 분류 · 규정 검사 · 잔액 계산

> ⚠ 아래 수치·키워드·금지 품목은 **기본값(가정)** 이다. 학교 실제 지침을 구하면 사람이 이 파일을 고친다.
> 코드에서는 전부 `src/config/`에만 두고, 로직에 숫자를 직접 쓰지 않는다.

## 예산 구분과 항목 (순서 = 화면·엑셀 표시 순서 = 분류 동점 시 우선순위)
| 구분 | 항목 |
|---|---|
| `rne` R&E 연구비 | 재료비, 소모품비, 도서·자료비, 인쇄비, 기타 |
| `club` 동아리 활동비 | 물품구입비, 인쇄비, 행사·체험비, 기타 |

## 자동 분류
품명(+ spec)에 키워드가 몇 개 들어 있는지 항목별로 센다. 가장 많은 항목으로 분류, 동점이면 위 표 순서가 빠른 항목, 0개면 `기타`.
대소문자 무시, 부분 문자열 일치. 사용자가 바꾼 항목은 다시 자동 분류하지 않는다.

| 키워드 묶음 | rne → | club → |
|---|---|---|
| **부품**: 아두이노, 라즈베리, ESP32, 센서, 모듈, 보드, 모터, 서보, 릴레이, 펌프, 저항, 콘덴서, 커패시터, LED, 트랜지스터, 기판, PCB, 브레드보드, 필라멘트, 아크릴, 프로파일, 기어, 베어링, 디스플레이, 카메라, 오실로스코프, 멀티미터, 전원공급기, 납땜인두 | 재료비 | 물품구입비 |
| **소모품**: 점퍼, 케이블, 전선, 납, 플럭스, 테이프, 글루, 건전지, 배터리, 호스, 나사, 볼트, 너트, 수축튜브, 케이블타이, 장갑, 사포 | 소모품비 | 물품구입비 |
| **도서**: 도서, 책, 교재, 논문, 자료집, 구독 | 도서·자료비 | 기타 |
| **인쇄**: 인쇄, 출력, 포스터, 현수막, 제본, 명함, 스티커 | 인쇄비 | 인쇄비 |
| **행사**: 입장, 체험, 참가비, 대관, 교통, 버스 | 기타 | 행사·체험비 |

분류 예 (테스트 케이스):
- "점퍼 케이블 M-M 20cm 40P" → 소모품 2개(점퍼, 케이블) → rne 소모품비
- "5V 1채널 릴레이 모듈" → 부품 2개 → rne 재료비
- "18650 리튬이온 배터리 3000mAh" → rne 소모품비
- "MG996R 메탈기어 서보모터" → 부품 2개(서보, 모터) → club 물품구입비
- "센서 공학 입문 (도서)" → 부품 1(센서) vs 도서 1(도서) 동점 → 표 순서상 재료비가 먼저 → rne 재료비. **이건 틀린 분류**이므로 사용자가 직접 도서·자료비로 바꿔야 한다 → 시드 REQ-0002는 category를 명시적으로 도서·자료비로 저장

## 배송비·부가세 귀속
배송비와 부가세(vatFee)는 품목표 맨 아래 별도 줄로 보여주고, 그 요청 안에서 **품목 금액 합이 가장 큰 항목**에 둘 다 귀속한다 (동점이면 표 순서). 품목이 0개면 `기타`. 요청 합계 = 품목 합 + 부가세 + 배송비. R2·R4 같은 합계 기준 규칙도 이 합계를 쓴다.

## 잔액 계산 (팀 단위, 항목별)
- `approved` = 상태가 승인인 요청들의 해당 항목 금액 합 (배송비·부가세 귀속 포함)
- `pending` = 상태가 승인 대기인 요청들의 해당 항목 금액 합
- `available` = 배정 − approved − pending
- 반려된 요청은 어디에도 넣지 않는다
- 새 요청을 검사할 때: "이번 요청 후 잔액" = available − 이번 요청의 해당 항목 금액. 재제출이면 자기 자신의 기존 pending은 빼고 계산한다
- 총액도 같은 방식 (모든 항목 합)

## 규정 검사
`checkRequest(team, requests, draft, now) → Finding[]`, `Finding { ruleId, severity, message, itemId?, category? }`
- **error**가 하나라도 있으면 제출·승인 불가
- **warning**은 각각 사유(1자 이상)를 입력하면 제출 가능. 사유는 `acknowledgements`에 저장되고 교사 화면·엑셀 비고에 보인다
- **info**는 표시만

| ID | 조건 | 심각도 | 메시지 예 |
|---|---|---|---|
| R1 | 항목의 이번 요청 후 잔액 < 0 | error | 재료비 잔액 초과 (84,700원 초과) |
| R2 | 총 이번 요청 후 잔액 < 0 | error | 총 예산 잔액 초과 (12,000원 초과) |
| R3 | 품목 단가 ≥ **300,000원** | warning | 휴대용 디지털 오실로스코프 2채널 100MHz 단가 329,000원 — 비품 의심, 지도교사와 사전 협의 필요 |
| R4 | 요청 합계(배송비 포함) ≥ **500,000원** | warning | 요청 합계 50만 원 이상 — 비교 견적 2개 필요 |
| R5 | 품명에 상품권, 기프티콘, 기프트카드, 선불카드, 포인트 충전, 캐시 충전 포함 (`충전기`·`충전 모듈`은 걸리면 안 됨) | error | 상품권류는 구매할 수 없음 |
| R6 | 품명에 간식, 음료, 과자, 식사, 도시락, 피자, 치킨, 커피 포함 | rne: error / club: 행사·체험비면 warning, 아니면 error | R&E 연구비로 식비 집행 불가 |
| R7 | 수량 < 1 또는 > 1,000, 또는 정수 아님 | error | 수량은 1~1,000 정수 |
| R8 | 단가 < 1 또는 정수 아님 | error | 단가를 입력하세요 |
| R9 | 항목이 `기타` | info | 예산 항목을 확인하세요 |
| R10 | 품목 0개 | error | 품목이 없습니다 |
| R11 | 용도(purpose) 공백 | error | 용도를 입력하세요 |
| R12 | 품목의 `url`이 비었거나 `http(s)://`로 시작하지 않음 (`config.requireProductLink`가 true일 때, 기본 true) | error | 상품 링크를 입력하세요 (학교 제출 필수) |
| R13 | 배송비(shippingFee) < 0 또는 정수 아님 | error | 배송비는 0 이상의 정수여야 합니다 |
| R14 | 부가세(vatFee) < 0 또는 정수 아님 | error | 부가세는 0 이상의 정수여야 합니다 |

## 수용 기준
- 데모 시나리오 숫자가 그대로 나온다: 시드 rne-3에 데모 장바구니 8품목 → R1(재료비 84,700원 초과) error 1개 + R3 warning 1개, 다른 finding 없음 (R9 없음: 8품목 모두 기타 아님. 입력은 `demo-cart.txt` + `demo-cart.html`을 같이 붙여넣어 링크가 모두 채워진 상태)
- 오실로스코프 삭제 후 → finding 없음, 재료비 이번 요청 후 잔액 244,300, 합계 112,000
- 각 규칙마다 걸리는 경우·경계값(299,999 / 300,000, 499,999 / 500,000, 잔액 정확히 0)·안 걸리는 경우 테스트
- 분류 예 5개가 전부 테스트
- 잔액 계산: 승인·대기·반려 섞인 시드에서 rne-3 재료비 available 317,700, club-robot 물품구입비 available 311,600

## 가정
<!-- 에이전트가 추가 -->
- 분류 매칭은 순수 부분 문자열 일치(substring, 겹침 허용)로 구현. "MG996R 메탈기어 서보모터" 예시는 본문 설명상 부품 매칭 2개(서보, 모터)지만, "메탈기어"에 "기어"도 부품 키워드로 포함돼 실제로는 3개가 매칭된다. 최종 분류 결과(물품구입비)에는 영향 없으므로 그대로 둔다.
- `checkRequest` 시그니처는 `(team, requests, draft, options?)`로 구현(스펙 표기의 `now` 파라미터는 생략). R1~R12 중 현재 시각을 쓰는 규칙이 없어 들고 있어도 쓸 데가 없는 죽은 파라미터가 되기 때문. 향후 시간 기반 규칙이 추가되면 다시 넣는다. `options.excludeRequestId`는 재제출 시 자기 자신의 기존 pending 제외용(기존 `remainingAfterDraft`와 동일한 패턴).
- R6(식비) 표의 메시지 예("R&E 연구비로 식비 집행 불가")는 rne 전용이고 club 쪽 문구는 스펙에 없어 직접 작성: club+행사·체험비(warning) "식비는 행사·체험비 지출 — 사유를 입력하세요", club+그 외(error) "동아리 활동비로 식비 집행 불가 (행사·체험비 항목만 가능)".
- 분류 키워드 묶음(`CLASSIFY_KEYWORD_GROUPS`)은 한글 키워드 외에 영문 품명(Arduino, ESP32, Raspberry Pi, Servo Motor, Breadboard, Jumper Wire, Battery 등)도 매칭하도록 영문 키워드를 같이 둔다. `classifyItem`이 `toLowerCase()`로 비교하므로 대소문자·혼합 표기(ArduinoUNO, RASPBERRY 등)는 키워드를 소문자로만 등록해도 전부 매칭된다(실시간 지시, iteration 47).
- 검수에서 배송비·부가세에 음수/소수를 넣어도 막히지 않는 버그가 발견돼 R13(배송비)·R14(부가세) error 규칙을 추가(실시간 지시, iteration 48). 기존 R1~R12는 번호를 건드리지 않고 뒤에 이어 붙였다. 두 필드를 하나의 규칙으로 합치지 않고 번호를 분리한 이유: 두 금액이 동시에 잘못돼도 각각 다른 메시지로 보여야 사용자가 어느 입력란이 문제인지 알 수 있어서.
