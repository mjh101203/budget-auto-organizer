# 05 · 화면

모바일보다 노트북 화면(1280px) 기준. 한국어. 금액은 항상 `12,300원` 형식 (오른쪽 정렬).
라우팅 라이브러리 없이 상단 내비게이션 + 화면 상태로 전환해도 된다.

## 공통 레이아웃
- 상단 바: 서비스 이름 "예산척척" · **역할 전환** 드롭다운 (`학생 · 김민준 (R&E 3팀)` / `학생 · 한도윤 (로봇공학 동아리)` / `교사 · 최윤서`)
- 하단: [데모 초기화] (확인 없이 시드로 되돌리고 첫 화면으로)
- 브라우저 alert/confirm 쓰지 않는다 (e2e가 멈춘다). 확인이 필요하면 화면 안 모달

## 학생 홈
- 팀 이름, 총 예산 카드 (배정 / 승인 집행 / 승인 대기 / 잔액)
- 항목별 카드: 막대 하나에 승인 집행(진한색)·승인 대기(옅은색)·잔액 표시, 숫자 4개
- 내 팀 요청 목록: 요청번호 · 날짜 · 용도 · 합계 · 상태 배지. 행 클릭 → 요청 상세
- [새 구매 요청] 버튼, (P1) [예산현황 엑셀]

## 새 구매 요청 (재제출도 같은 화면, 기존 내용 채워진 상태)
1. **붙여넣기 영역** (여러 줄 입력; 붙여넣기 이벤트에서 text/plain과 text/html을 둘 다 읽는다) + [인식] 버튼 + 작은 글씨 안내 "쇼핑몰 장바구니 화면을 전체 선택해서 복사한 뒤 붙여넣으세요"
2. **파싱 경고** 박스 (있을 때만): 경고 목록, UNPARSED_LINE은 그 줄 원문 + [품목으로 추가](P1)
3. **품목표**: 연번 · 품명(편집) · 규격(편집) · 링크(편집, 비면 빨간 테두리) · 수량(숫자 입력) · 단가(숫자 입력) · 금액(계산) · 예산 항목(드롭다운) · [삭제]. 아래 [행 추가], 배송비 입력칸, 합계
4. **규정 검사 패널** (품목표 오른쪽 또는 아래, 입력 바뀔 때마다 즉시 재계산)
   - error 빨강, warning 주황(사유 입력칸 포함), info 회색. 해당 품목 행도 같은 색으로 테두리
   - 항목별 "현재 잔액 → 이번 요청 후 잔액" 표 (음수는 빨강)
5. 용도 입력 + [제출] (error 있거나 사유 없는 warning 있으면 비활성, 비활성 이유를 버튼 옆에 한 줄로)
6. 제출 성공 → 요청 상세로 이동, 상단에 "REQ-0004 제출됨"

## 요청 상세
- 상태 배지, 요청 정보, 품목표(읽기 전용), 경고 사유, 이력 타임라인
- 학생: 반려면 반려 사유 + [수정 후 재제출], 승인이면 [품의서 엑셀]
- 교사: 승인 대기면 재검사 결과 + [승인] / [반려] (반려는 사유 입력 모달)

## 교사 홈
- 승인 대기 목록 (오래된 순): 팀 · 요청번호 · 요청일 · 합계 · 경고 수
- (P1) 팀별 집행률 막대 2개
